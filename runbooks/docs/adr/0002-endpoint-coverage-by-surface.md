# Endpoint coverage is per surface when the stack has API runbooks

`ui` runbooks list the API endpoints their screens call in `covers.entries`, so `list --affected` finds the screen when an endpoint changes. In a `backend` or `fullstack` stack, those references no longer count as coverage. An `api-endpoint` is covered only through an `api` runbook, and a `ui-route` only through a `ui` runbook. Without this rule, a fullstack screen would cover its endpoints by itself, `map` would never propose `api` placeholders for them, and `api` runbooks would only appear for webhooks. A `frontend` stack keeps the old rule, because it has no `api` runbooks to cover its route handlers. Existing fullstack projects see endpoint coverage drop on the first `coverage` after they set `stack`. `setup` and `upgrade` warn about it.
